# Архитектура

Проект — **монорепозиторий**: эмулятор устройства и мобильный клиент живут рядом.
Всё устройство эмулируется программно: Raspberry Pi и датчик-спектрометр не покупаются.

```
LightningSystem/
├── docs/       эта документация
├── device/     эмулятор устройства (Python)
└── android/    клиент (Java, Android Studio)
```

Клиент обращается **напрямую к устройству** по локальной сети через REST API.
Отдельного сервера нет: в эмуляции «сервер» и есть эмулятор устройства.

## Модули устройства (Python)

| Модуль | Ответственность |
|---|---|
| `domain` | сущности и правила: Объект, Рабочее место, Лампа, Датчик, Замер |
| `hal` | интерфейсы драйверов: `LightDriver`, `SensorDriver`, `PowerMeter`, `Clock` |
| `sim` | виртуальное железо: физика света и мощности (реализует `hal`) |
| `policy` | авторегулятор: целевые lux -> уставка яркости |
| `storage` | персистентность: реестры, места, режимы, уставки, привязки, история |
| `telemetry` | запись замеров и агрегация за период |
| `service` | сценарии использования, сводит модули вместе |
| `api` | HTTP-транспорт: роуты, DTO, ошибки (**без логики**) |
| `runtime` | конфиг, выбор `virtual`/`hardware`, планировщик, запуск |

Направление зависимостей — в одну сторону, без циклов:

```
api -> service -> { domain, policy, storage, telemetry }
sim -> hal
domain -> (ничего)    hal -> (ничего)    runtime -> всё
```

`domain`, `hal`, `sim`, `policy` — «чистые» модули: не знают ни про HTTP, ни про базу.
Это позволяет при необходимости вынести их на отдельный сервер без переписывания.

## Модули клиента (Android, Java)

| Модуль | Ответственность |
|---|---|
| `:app` | Activity, навигация, экраны |
| `:core:model` | доменные модели |
| `:core:network` | Retrofit, DTO, маппинг |
| `:core:data` | Repository, настройки, кэш |
| `:feature:*` | экраны по функциям (на старте — пакеты внутри `:app`) |

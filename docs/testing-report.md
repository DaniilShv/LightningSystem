# Отчёт о тестировании

> **Статус: черновик.** Отражает состояние на 23.11.2026 (ветка `feature/rooms-api`, коммит `1cd151d`).
> Разделы про цикл опроса датчиков, учёт энергии, историю, эндпоинты `/sim/*` и Android-клиент будут дополнены, когда эти части будут готовы.

## 1. Что тестируется

**LightningSystem** — система управления освещением на Raspberry Pi (задание — в [README.md](../README.md)).

| Часть | Где | Состояние на дату отчёта |
|---|---|---|
| Программа устройства | `device/` | комнаты, лампы, датчики, привязки, ручное управление, плавный переход, авто-регулятор, хранение в SQLite, REST API |
| REST API | `docs/api.md` | реализованы `/health`, `/auth/check`, `/site`, `/rooms`, `/lamps`, `/sensors`; нет `/energy`, `/sensors/{id}/readings`, `/sim/*` |
| Веб-эмулятор | `simulator/index.html` | работает автономно, без подключения к устройству |
| Android-клиент | ветка `feature/beresnev` | концепт экранов без сети, **не тестировался** |

## 2. Окружение

| | |
|---|---|
| ОС | Windows 11 Pro |
| Python | 3.15.0 |
| Библиотеки | fastapi 0.155.0, starlette 1.9.0, uvicorn 0.54.0, pydantic 2.14.1, pydantic-settings 2.16.1, gpiozero 2.0.1, smbus2 0.6.1 |
| Тесты | pytest 9.1.1, httpx 0.28.1 (`fastapi.testclient.TestClient`) |
| Режим | `RUNTIME=virtual` — виртуальное железо; часть тестов запускает `RUNTIME=hardware` на виртуальных ножках |

**Настоящей Raspberry Pi, ламп и датчика нет.** Поэтому:
- драйверы ламп `GpioLight` проверены на виртуальных ножках gpiozero (`MockFactory` с `MockPWMPin`) — как на Pi, но без электричества;
- драйвер датчика `Tcs34725Sensor` проверен на двойнике шины I2C, который запоминает обращения и отдаёт заданные байты. Это проверяет, *что* драйвер отправляет на шину, но не то, *как ответит* настоящий чип;
- тесты запускались только на Python 3.15, а на Pi обычно Python 3.11–3.13.

## 3. Методика

Тесты повторяют слои из [architecture.md](architecture.md): каждый слой проверяется отдельно, а потом вся цепочка вместе.

| Уровень | Что проверяет | Чем | Файлы |
|---|---|---|---|
| Модель (`domain`) | сущности, формулы каналов, плавный переход, правила-инварианты | обычные вызовы функций, без базы и сервера | `test_domain_light.py`, `test_domain_rules.py` |
| Регулятор (`policy`) | формула авто-режима: мёртвая зона, шаг, ограничения | обычные вызовы | `test_policy_auto.py` |
| Виртуальное железо (`sim`) | физика света, инерция и шум датчика, обрыв провода, мощность, ускорение времени | обычные вызовы, ручные часы | `test_sim_*.py`, `test_virtual_clock.py` |
| Драйверы Pi (`hardware`) | ножки реле и ШИМ, порядок включения, регистры TCS34725, мультиплексор, ошибки шины | gpiozero `MockFactory`, двойник шины I2C | `test_hardware_*.py` |
| Хранение (`storage`) | чтение и проверка `device.toml`, таблицы, сохранение между перезапусками | временная база SQLite (в памяти и в файле) | `test_storage.py` |
| Сценарии (`service`) | создание комнат, привязки, управление, ошибки 404/409, цикл вывода | база в памяти + виртуальные лампы | `test_service_lighting.py` |
| Авто-режим целиком | сходимость регулятора к цели, устойчивость к шуму, потеря датчика | замкнутый контур: `service` + виртуальные лампы и датчики на параметрах из `device.toml`, замер раз в секунду | `test_auto_mode.py` |
| REST API | коды ответов, форма JSON по `docs/api.md`, API-ключ, Swagger | `TestClient`, временная база | `test_api_system.py`, `test_api_rooms.py` |
| Запуск (`runtime`) | запуск в `virtual` и `hardware`, цикл вывода в фоне, гашение ламп при остановке, сквозной авто-режим через API | `TestClient` с запуском приложения целиком | `test_runtime.py` |
| Ручные проверки | работа сервера и эмулятора глазами | uvicorn + Swagger, браузер | раздел 6 |

Запуск всех тестов:

```bash
cd device
.venv/Scripts/python -m pytest -q
```

## 7. Найденные и исправленные дефекты

| № | Где | Дефект | Как нашли | Исправление |
|---|---|---|---|---|
| 1 | драйвер TCS34725 | адреса регистров без командного бита `0x80` (и без автоинкремента для чтения блока) — по даташиту чип не принял бы настройку | чтение кода по даташиту | командный бит и автоинкремент, тесты на адреса регистров |
| 2 | драйвер TCS34725 | сбой мультиплексора выдавал `OSError`, а не `SensorError` — подсчёт «3 ошибки подряд» мог не сработать | проверочный скрипт с двойником шины | выбор канала внутри `try`, тест |
| 3 | драйвер TCS34725 | при отсутствии датчика на старте устройство падало при создании драйвера | чтение кода | настройка датчика при первом чтении и после сбоя, тесты |
| 4 | реестр железа | один датчик без канала мультиплексора при двух на каналах — оба ответили бы по одному адресу | чтение конфигурации | у каждого датчика свой канал, проверка при чтении реестра |
| 5 | реестр железа | в комментарии каналы `1..8`, у чипа `0..7`; канал 8 отправлял в мультиплексор 256 | проверочный скрипт | диапазон 0..7, проверка в драйвере и реестре |
| 6 | интерфейсы `hal` | счётчик мощности отдавал только сумму, а API и учёт энергии нужны по лампам; у драйвера ламп не было `close()` | сверка интерфейсов с `docs/api.md` и `architecture.md` | `power_by_lamp_w()` и `LightDriver.close()` |
| 7 | эмулятор | датчик не видел свет ламп — ночью авто-режим поднимал уставку до 100 % | чтение кода, проверка в браузере | показания по формуле `model.md` (дневной свет + лампы) |
| 8 | эмулятор | при запуске лампы были тёмными, хотя уставка комнаты 40–70 % | чтение кода | лампы получают уставку комнаты при запуске |
| 9 | API | в первой версии DTO необязательные поля стали бы обязательными | чтение кода до запуска тестов | ограничения полей через `Annotated`, тесты 422 |

## 8. Известные ограничения и открытые вопросы

- **Нет проверки на настоящем железе.** Драйверы Pi проверены только на виртуальных ножках и двойнике шины. Особенно нужна проверка TCS34725 (дефект 1 исправлен по даташиту, не на чипе).
- **В запущенном устройстве нет цикла опроса датчиков** (зона Максима): датчики оффлайн, `auto` отвечает 409. Логика авто-режима проверена в тестах с ручным опросом.
- **Не реализованы и не тестировались:** циркадный режим, учёт энергии и история, `/energy`, `/sensors/{id}/readings`, `/sim/*`, подключение эмулятора к устройству.
- **Android-клиент не тестировался.**
- **Эмулятор расходится с моделью:** в нём нет правила «регулятор ждёт, пока лампы дойдут до уставки», а плавный переход сделан по долям ШИМ, а не функцией `approach` из `model.md`.
- **Нагрузочное тестирование и долгая работа** (часы, сутки) не проводились.
- **Покрытие кода** не измерено (см. раздел 4).

## 9. Вывод

На дату отчёта программа устройства в режиме `virtual` выполняет ручное управление комнатами через REST API: включение и выключение, яркость, оттенок, привязки, сохранение между перезапусками. Все 194 автотеста проходят, все 14 инвариантов модели покрыты тестами. Авто-регулятор сходится к цели без раскачки в замкнутом контуре на виртуальном железе.

До готовности прототипа по критериям из README не хватает: цикла опроса датчиков в устройстве, учёта энергии и графика, Android-клиента и проверки на настоящей Raspberry Pi. Эти разделы отчёта будут дополнены.

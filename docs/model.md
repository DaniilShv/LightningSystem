# Модель предметной области

## Иерархия

```
Объект (квартира, офис — одно устройство управляет одним объектом)
├── реестр ламп      (лампа существует и вне комнаты)
├── реестр датчиков
└── комнаты          (единица управления, создаются в рантайме)
```

**Комната** — единица управления (в первом концепте называлась «рабочее место»). Датчик и лампы только ссылаются на неё.
Реестры ламп и датчиков заполняются из `device/device.yaml`, то есть из того, что физически подключено. Комнаты создаёт пользователь.

## Сущности

| Сущность | Поля |
|---|---|
| Объект | имя, тариф ₽/кВт·ч, циркадная кривая |
| Комната | id, имя, режим (`manual`/`auto`), уставка яркости 0..100, последняя уставка, целевые lux, режим оттенка (`manual`/`circadian`), уставка цветовой температуры K |
| Лампа | id, имя, привязка к комнате (0..1), фактическая яркость 0..100, фактическая цветовая температура K, диапазон K (2700..6500), максимальная мощность Вт, подключение (ножки реле / тёплого / холодного канала) |
| Датчик | id, имя, привязка к комнате (0..1), освещённость lux, цветовая температура CCT, статус онлайн/оффлайн, подключение (шина, канал мультиплексора) |
| Замер | время, датчик, комната, lux, CCT |
| Энергия | время, лампа, комната **на момент замера**, Вт·ч |

Показания датчика — **только две величины**: освещённость и цветовая температура.

## Инварианты

1. Лампа состоит максимум в одной комнате; свободная лампа живёт в реестре.
2. Датчик привязан максимум к одной комнате, у комнаты — максимум один датчик.
3. Удаление комнаты лампы и датчик не удаляет — только отвязывает.
4. Все лампы комнаты получают уставку комнаты: яркость и цветовую температуру.
5. Яркость 0 = выключено, отдельного флага «включено» нет.
6. «Включить» = вернуть последнюю ненулевую уставку (если её нет — 100). «Выключить» = уставка 0.
7. `auto` невозможен без привязанного датчика в статусе «онлайн».
8. Потеря датчика: режим → `manual`, текущая уставка остаётся (свет не скачет). Датчик вернулся — авто сам не включается.
9. Ручное действие пользователя с яркостью (вкл/выкл, ползунок) в режиме `auto` переводит комнату в `manual`. Ручное изменение оттенка переводит в `manual` режим оттенка. Режимы яркости и оттенка независимы.
10. Уставка (намерение) и фактическая яркость (применённое) — разные величины: фактическая плавно догоняет уставку.
11. Комнаты, режимы, уставки, привязки, реестры и история сохраняются между запусками.
12. История энергии не «переезжает»: если лампу перенесли в другую комнату, старые Вт·ч остаются за прежней.

## Управление

```
датчик {lux, CCT} -> режим комнаты -> уставка яркости   -> все лампы комнаты
                       manual: задана руками                (плавный переход)
                       auto:   подбирается под целевые lux
время суток       -> режим оттенка -> уставка K         -> все лампы комнаты
                       manual: задана руками
                       circadian: по циркадной кривой
                                       └> замеры и энергия -> сводка по комнате -> объекту
```

### Авто-режим (`policy`)
Датчик стоит в комнате и видит **весь** свет: дневной и от самих ламп. Поэтому регулятор работает «по обратной связи», маленькими шагами, раз в секунду:

```
error = target_lux - lux
если |error| <= 10% от target_lux -> ничего не меняем (мёртвая зона, чтобы свет не дёргался)
иначе уставка += clamp(0.5 * error / target_lux * 100, -10, +10), затем clamp(0, 100)
```

Стало светло на улице — уставка сама опускается до 0 (свет выключен). Стемнело — поднимается.

### Циркадный режим (`policy`)
Цветовая температура по времени суток, линейно между опорными точками (кривая хранится у объекта):

| Время | 00:00 | 06:00 | 09:00 | 13:00 | 17:00 | 20:00 | 22:00 |
|---|---|---|---|---|---|---|---|
| K | 2700 | 2700 | 5000 | 6000 | 5000 | 3500 | 2700 |

Днём свет холоднее, вечером теплее. Работает и при выключенном свете: включили вечером — сразу загорается тёплым.

### Плавный переход (`domain`)
Фактическая яркость догоняет уставку с ограниченной скоростью: 0 → 100 % за `FADE_MS` (по умолчанию 600 мс). Фактическая цветовая температура догоняет так же: 2700 → 6500 K за `FADE_MS`. Это чистая функция `approach(actual, setpoint, dt)`, её вызывает цикл вывода примерно 30 раз в секунду.

## От уставки к ножкам (`domain` → `LightDriver`)

Глаз воспринимает яркость нелинейно, поэтому яркость в интерфейсе — **воспринимаемая**, а на ножки идёт «физическая» доля (гамма-коррекция):

```
duty  = (brightness / 100) ^ 2.2          # общая доля света
t     = (K - 2700) / (6500 - 2700)        # 0 = только тёплый, 1 = только холодный
warm  = (1 - t) * duty                    # ШИМ тёплого канала, 0..1
cool  = t * duty                          # ШИМ холодного канала, 0..1
relay = brightness > 0
```

При включении реле замыкается сразу, при выключении — когда ШИМ уже погас.

## Физика (`sim`)

Простая модель: правдоподобная, но без спектров и геометрии.

**Дневной свет.** На улице — кривая по времени суток (рассвет около 7:00, закат около 17:30, пик около 900 lux у окна). В комнату попадает `D = уличный × окно`, где «окно» — коэффициент комнаты 0..1 из конфига `sim`. Цветовая температура дневного света — 6500 K.

**Вклад лампы** в показания датчика её комнаты:
```
E_i = lux_at_full_i * duty_i        # lux_at_full — сколько lux даёт лампа на 100 %, из конфига sim
```
Позже `lux_at_full` можно считать из расстояния до датчика: `E = I / d²`.

**Показания датчика:**
```
lux = D + Σ E_i
CCT = (D * 6500 + Σ E_i * K_i) / lux            # если lux < 1 — CCT не определена
измерено = lux * (1 + шум ±2 %), с инерцией: m += (lux - m) * dt / τ, τ = 1 с
```

**Мощность и энергия** (`PowerMeter`):
```
P_i  = max_power_w_i * duty_i        # реле разомкнуто -> 0 Вт
Вт·ч += P_i * dt / 3600
₽    = кВт·ч * тариф
```
Мощность считается от `duty`, а не от воспринимаемой яркости. Поэтому 50 % яркости «на глаз» — это всего около 22 % мощности. Тусклый свет заметно экономит электричество.

**Неисправности.** У виртуального датчика можно «оборвать провод»: чтение бросает ошибку, как настоящий smbus2. После 3 ошибок подряд датчик «оффлайн».

**Время.** Виртуальные часы можно перемотать (утро, вечер) и ускорить (×1, ×60, ×600), чтобы показать авто-режим, циркадный режим и графики энергии без долгого ожидания.

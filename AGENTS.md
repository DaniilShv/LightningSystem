# AGENTS.md

Инструкции для ИИ-ассистентов (Claude Code, Codex, Cursor и др.), с которыми работают участники команды. Людям тоже полезно прочитать: здесь собраны главные договорённости проекта.

## О проекте

**LightningSystem** — учебный проект: система управления освещением в помещении на Raspberry Pi. Задание и участники — в [README.md](README.md).

- **Устройство** (`device/`) — Python + FastAPI. Программа «на Raspberry Pi» управляет лампами (ШИМ и реле через GPIO) и читает датчики освещённости (I2C).
- **Клиент** (`android/`) — Android-приложение на Java, обращается к устройству напрямую по локальной сети через REST API.
- **Железа нет.** Всё эмулируется программно (`RUNTIME=virtual`), запуск — на обычном ПК. На настоящей Pi меняются только драйверы (`RUNTIME=hardware`).

**Объясняй решения простыми словами**, а термины (ШИМ, I2C, MOSFET, HAL и т. п.) поясняй одной фразой при первом упоминании.

## Текущее состояние

- ✅ Документация: архитектура, модель, API.
- ✅ Веб-эмулятор — [simulator/index.html](simulator/index.html): один файл, работает без устройства. **Построен на старой модели** (режим у каждой лампы, флаг `is_on`, расписания), его нужно перевести на модель из `docs/model.md`: комната — единица управления, яркость 0 = выключено.
- 🟡 Устройство (`device/`): есть каркас. Пакет `lighting/` разбит на модули из `docs/architecture.md`, работают конфиг, `GET /health`, проверка `X-API-Key`, `GET /auth/check`, `hal.Clock` и `sim.VirtualClock`. Остальные модули пока пустые, в них только docstring с назначением.
- ⏳ Android-клиент (`android/`).

## Ключевые правила

1. **Слои и зависимости** — строго как в `docs/architecture.md`. `domain`, `hal`, `policy`, `sim` — чистые модули: без HTTP, базы данных и asyncio.
2. **Железо** трогают только реализации `hal` (`sim`, `hardware`). gpiozero и smbus2 импортируются только в `hardware`.
3. **Состояние меняет только `service`.** `api` без логики, `policy` только возвращает решения (новую уставку), но сама ничего не применяет.
4. **Комната — единица управления.** Лампы получают уставку комнаты. Яркость 0 = выключено. Уставка и фактическая яркость — разные величины.
5. **Время** — только через `Clock` из `hal`. `datetime.now()` и `time.time()` в логике не используем.
6. **Инварианты** из `docs/model.md` проверяются тестами. Новое правило — сначала в документ, потом в код и тест.
7. **API-ключ** (`X-API-Key`) обязателен для всего, кроме `GET /health`. Ключи и `.env` не коммитим.
8. Эндпоинты `/sim/*` существуют только при `RUNTIME=virtual`.

## Правила кода

**Общее**
- Идентификаторы (переменные, функции, классы, поля API) — на **английском**. Комментарии, docstring, тексты интерфейса, сообщения для пользователя, документация — на **русском**.
- Пиши как окружающий код: тот же стиль, плотность комментариев и подход. Без лишних абстракций «на будущее».
- Не добавляй зависимости без необходимости. Если добавляешь — объясни, зачем.

**Устройство (Python)**
- Python 3.11+, FastAPI, pydantic-settings, SQLite через стандартный `sqlite3` (только внутри `storage`), pytest + httpx.
- Сущности `domain` — обычные dataclass без привязки к базе. `storage` переводит их в таблицы и обратно, DTO для HTTP живут в `api`.
- Любая новая функция сопровождается тестом. `domain` и `policy` тестируются без базы и сервера, API — через `TestClient` на `RUNTIME=virtual`, драйверы `hardware` — через gpiozero `MockFactory`.
- Фоновые циклы не падают от исключения: пишут ошибку в лог и продолжают работу.

**Эмулятор (`simulator/index.html`)**
- Один самодостаточный HTML-файл без сборки и внешних зависимостей: открывается двойным щелчком.
- Внутри два блока: «Движок» (эмуляция устройства) и «Отрисовка». Позже «Движок» заменится подключением к `device/` по REST; демо-режим без устройства оставим переключателем.
- Формулы движка должны совпадать с `docs/model.md`.

## Команды

```bash
cd device
python -m venv .venv
.venv/Scripts/activate            # Windows; на Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # затем вписать API_KEY
python -m lighting.runtime.gen_key             # сгенерировать API-ключ
uvicorn lighting.runtime.main:app --reload     # Swagger: http://localhost:8000/docs
pytest
```

Все команды запускаются из `device/`. Новый роутер подключай к `protected` в `api/router.py`: так проверка ключа включится для него автоматически.

Эмулятор: открыть `simulator/index.html` в браузере.

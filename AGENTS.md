# AGENTS.md

Инструкции для ИИ-ассистентов

## О проекте

**LightningSystem** — учебный проект: система управления освещением в помещении на Raspberry Pi. Задание и участники — в [README.md](README.md).

- **Устройство** (`device/`) — Python + FastAPI. Программа «на Raspberry Pi» управляет лампами (ШИМ и реле через GPIO) и читает датчики освещённости (I2C).
- **Клиент** (`android/`) — Android-приложение на Java, обращается к устройству напрямую по локальной сети через REST API.
- **Железа нет.** Всё эмулируется программно (`RUNTIME=virtual`), запуск — на обычном ПК. На настоящей Pi меняются только драйверы (`RUNTIME=hardware`).

**Объясняй решения простыми словами**, а термины (ШИМ, I2C, MOSFET, HAL и т. п.) поясняй одной фразой при первом упоминании.

## Как работать

### Код должен быть понятен студенту

Проект учебный: код читают, поддерживают и защищают участники команды

- Простые явные конструкции: функции, обычные классы и dataclass, `async/await` там, где он разрешён (`service`, `runtime`, `api`). Без метаклассов, monkey-patching, динамической загрузки модулей (`importlib`), хитрых декораторов и прочей «магии».
- Понятные имена вместо комментариев. Комментарий пишем там, где без него не понять, *почему* сделано так.
- Маленькие шаги: одна задача за раз. Соседний код без просьбы не рефакторим.
- После изменений коротко объясни, что сделал и почему

### Сложные решения — только после объяснения

Если, по-твоему, нужен паттерн, библиотека или подход сложнее описанного здесь и в `docs/`, сначала объясни:
1. какую проблему он решает именно в нашем проекте;
2. как выглядит простое решение без него и чем оно хуже;
3. чего это будет стоить: новые понятия, файлы, зависимости.

Внедряй только после согласия.

Без согласования не используем: ORM (SQLAlchemy, SQLModel) и миграторы, DI-контейнеры, брокеры сообщений и очереди задач (Celery, Redis), Docker, отдельный сервер БД, генерацию клиента по OpenAPI. Любую новую библиотеку тоже добавляем только после объяснения.

## Ключевые правила

1. **Слои и зависимости** — строго как в `docs/architecture.md`. `domain`, `hal`, `policy`, `sim` — чистые модули: без HTTP, базы данных и asyncio. Циклические зависимости запрещены: если без цикла не обойтись, остановись и предложи решение с объяснением.
2. **Железо** трогают только реализации `hal` (`sim`, `hardware`). gpiozero и smbus2 импортируются только в `hardware`.
3. **Состояние меняет только `service`.** `api` без логики, `policy` только возвращает решения (новую уставку), но сама ничего не применяет.
4. **Комната — единица управления.** Лампы получают уставку комнаты. Яркость 0 = выключено. Уставка и фактическая яркость — разные величины.
5. **Время** — только через `Clock` из `hal`. `datetime.now()` и `time.time()` в логике не используем.
6. **Инварианты** из `docs/model.md` проверяются тестами. Новое правило — сначала в документ, потом в код и тест.
7. **API-ключ** (`X-API-Key`) обязателен для всего, кроме `GET /health`. Ключи и `.env` не коммитим, ключ не пишем в лог и не возвращаем в ответах.
8. Эндпоинты `/sim/*` существуют только при `RUNTIME=virtual`.
9. **Контракт API — [docs/api.md](docs/api.md).** Устройство и Android-клиент пишут разные люди, поэтому эндпоинты, поля и коды ошибок не придумывай сам. Изменение контракта согласуется с командой и сначала вносится в `api.md`.
10. **Зоны участников** — в разделе «Роли» `docs/architecture.md`. Если задача требует менять чужую зону (например, `android/` при работе над устройством), предупреди об этом до правки.

## Правила кода

**Общее**
- Идентификаторы (переменные, функции, классы, поля API) — на **английском**. Комментарии, docstring, тексты интерфейса, сообщения для пользователя, документация — на **русском**.
- Пиши как окружающий код: тот же стиль, плотность комментариев и подход. Без лишних абстракций «на будущее».
- Новые зависимости — только по правилам раздела «Сложные решения — только после объяснения».

**Устройство (Python)**
- Python 3.11+, FastAPI, pydantic-settings, SQLite через стандартный `sqlite3` (только внутри `storage`), pytest + httpx.
- Сущности `domain` — обычные dataclass без привязки к базе. `storage` переводит их в таблицы и обратно, DTO для HTTP живут в `api`.
- Любая новая функция сопровождается тестом. `domain` и `policy` тестируются без базы и сервера, API — через `TestClient` на `RUNTIME=virtual`, драйверы `hardware` — через gpiozero `MockFactory`.
- Фоновые циклы не падают от исключения: пишут ошибку в лог и продолжают работу.
- Прежде чем сказать «готово», прогони `pytest`.

**Swagger**
- Swagger (`/docs`) строит сам FastAPI, отдельно его не подключаем.
- У каждого эндпоинта есть `summary` на русском, тег группы и DTO ответа (тип возврата или `response_model`). Возможные коды ошибок из `docs/api.md` указываем в `responses`.
- Новый или изменённый эндпоинт после правки должен корректно отображаться в Swagger, закрытые — проверяться через кнопку «Authorize».

**Эмулятор (`simulator/index.html`)**
- Один самодостаточный HTML-файл без сборки и внешних зависимостей: открывается двойным щелчком.
- Внутри два блока: «Движок» (эмуляция устройства) и «Отрисовка». Позже «Движок» заменится подключением к `device/` по REST; демо-режим без устройства оставим переключателем.
- Формулы движка должны совпадать с `docs/model.md`.

## Команды

```bash
cd device
python -m venv .venv
.venv/Scripts/activate            # Windows; на Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # затем вписать API_KEY
python -m lighting.runtime.gen_key             # сгенерировать API-ключ
uvicorn lighting.runtime.main:app --reload     # Swagger: http://localhost:8000/docs
pytest
```

Все команды запускаются из `device/`. Новый роутер подключай к `protected` в `api/router.py`: так проверка ключа включится для него автоматически.

Эмулятор: открыть `simulator/index.html` в браузере.

## Git

- Основная ветка — `main`, разработка идёт в `dev`. Новые задачи — в отдельных ветках от `dev` (`feature/<кратко>`), слияние в `dev` через Pull Request.
- Коммить, пушь и мержи **только когда участник команды об этом попросил**. Напрямую в `main` и `dev` агент не коммитит никогда.
- Сообщения коммитов — короткие, в повелительном наклонении («Добавить авто-режим комнаты»).
- Не коммить: `.env`, базы `*.db`, `.venv/`, `__pycache__/`, файлы IDE, личные заметки (`/notes`).
